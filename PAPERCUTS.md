# Papercuts
- The full test suite intermittently fails `spawned_pty_processes_receive_a_capable_terminal_type` because the PTY emits `xterm-256color\r\n` while the assertion expects no line ending, despite passing in an immediately prior run. Normalize PTY line endings or trim CR/LF in that assertion.
- While auditing the active model prompt, `prompts/system-initial.md` looked like an active bootstrap prompt but is tracked, unused, and has no explanation of its archival purpose, causing a detour through history and call sites. Rename or move it to a clearly historical location, or add a short provenance/purpose header.
- This host's installed `nc` does not support Unix-domain sockets (`-U`), and `socat` is unavailable, so ad hoc relay/socket smoke tests cannot assume either utility. Use a repository test helper or a standard-library Unix socket client/server instead.
- With both `origin` and `upstream` remotes configured, an unqualified `gh pr list` resolves to `openai/codex` instead of the BetterCodex repository, producing a convincing but irrelevant PR audit. Pin repository-scoped GitHub CLI commands with `-R ummay0432/bettercodex` (or document/configure the expected default).
- The repository setup appeared to have `cargo-nextest` available, but the active rustup Cargo toolchain reported `no such command: nextest`. Document a reliable `cargo nextest --version` preflight or installation command that works with the pinned toolchain, and keep `cargo test` as the validation fallback.
- The documented `cargo install --locked just` setup can succeed while `just` remains unavailable because `$HOME/.cargo/bin` is absent from the agent shell's PATH. Document a PATH check or show an absolute-path fallback after installing Cargo CLI tools.
- `command -v time` can report Bash's `time` keyword even though `/usr/bin/time` is absent, causing benchmark scripts that invoke the binary path to fail. Use Bash `TIMEFORMAT` with the `time` reserved word, or explicitly test `-x /usr/bin/time`, before timing commands.
- A fresh Cargo target in a temporary worktree can exhaust this host's filesystem before BetterCodex reaches project compilation, while the primary checkout already has a warm multi-gigabyte target. Check `df`/target sizes before isolated builds; reuse a known-safe target or clean stale Rust artifacts first.
- A clean BetterCodex validation target consumes about 5.7 GB, so placing isolated CARGO_TARGET_DIR values under this host's 12 GB `/tmp` tmpfs can fail with ENOSPC when another validation runs concurrently. Document a disk-backed validation target (or a `/tmp` capacity preflight) and clean it with `cargo clean --target-dir` afterward.
- Startup-performance work has no documented profiling baseline and this environment lacks hyperfine, strace, perf, and /usr/bin/time. Document/install a lightweight benchmark/profiler toolchain (at minimum hyperfine and strace) so launch regressions can be measured consistently.
- The long-command wrapper returned a `session_id`, while `functions.wait` documented a required `cell_id` and rejected that identifier. Clarify that raw command sessions must be polled with `write_stdin`, or return both identifiers consistently.
- Concurrent agent cleanup can delete the repository’s shared `target/` while another Cargo command is active, causing cascades of missing `.rlib`, fingerprint, and dep-info errors. Validation sessions should use a task-specific `CARGO_TARGET_DIR` outside the checkout, and cleanup should avoid artifact directories with live Cargo/rustc owners.
- Sharing one CARGO_TARGET_DIR across worktrees can make Cargo reuse a package binary when the second worktree has older source mtimes, invalidating A/B measurements. Before cross-worktree benchmarks, clean the package outputs (`cargo clean -p bettercodex`) while retaining dependency artifacts, or use distinct targets.
- Concurrent sessions share the main worktree’s Git index, so another session can commit or stage files between `git add` and `git commit`; this produced a valid commit with an unrelated message. Serialize shared-index commits or give each agent a separate Git worktree/index, and verify `git diff --cached` immediately before committing.
- A concurrent validation cleanup removed `/home/user/monorepo/bettercodex-startup-target` while Cargo was actively building in it, causing widespread missing-object failures. Cleanup jobs must delete only targets they own and first verify that no Cargo/Rust process references the path.
- The OpenAI Docs search can return learn.chatgpt.com/docs/changelog, but fetch_openai_doc rewrites/fetches it as changelog.md and gets a 404. The search/fetch index should only return retrievable URLs or preserve the site's supported route format.
- An older installed `bcodex` can treat the newer `bcodex update` syntax as an ordinary interactive prompt, silently starting an agent that may recursively launch another session. Before using the updater, detect command support from the installed binary (or use the repository installer/direct atomic install for pre-updater revisions).
- Focused Rust tests in this binary-only crate fail immediately with `cargo test --lib` (`no library targets found`), while the development guide does not call out the target shape. Document using `--bin bcodex` (or omitting a target selector) for filtered tests.
- The release-size benchmark expected GNU /usr/bin/time, but this development host does not provide it. Document a portable timing helper or include the required package in the development-host prerequisites.
- Running `cargo info` from the repository root resolves repository patches and updated every Git dependency even though only one crates.io package was being inspected. Run dependency probes from an isolated scratch manifest/cwd (and temporary CARGO_HOME) to avoid that latency and cache churn.
- Concurrent coding sessions shared the same disposable Rust target under /tmp; one session removed it while another was still benchmarking verified artifacts. Give each session a distinct tracked temporary root, or coordinate ownership before automatic cleanup.
