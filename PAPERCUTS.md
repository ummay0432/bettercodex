# Papercuts
- `gh` commands in this checkout can infer the read-only `upstream` remote (`openai/codex`) instead of origin, causing misleading 404s for bettercodex workflows. Repository docs or Git config should make `ummay0432/bettercodex` the unambiguous gh default, or examples should consistently pass `-R ummay0432/bettercodex`.
- A locally installed `x86_64-pc-windows-msvc` Rust target makes Linux cross-checks look available, but `cargo check --target x86_64-pc-windows-msvc` fails deep in native dependencies when `lib.exe` and an MSVC-compatible C toolchain are absent. Windows validation must run directly on a native Windows machine with the documented MSVC prerequisites; the Rust target alone is not a useful preflight.
- Running `cargo test` currently fails in the `v8 150.4.0` build script because it requests a nonexistent rusty_v8 prebuilt archive URL and receives HTTP 404 before project tests compile. Document a supported validation setup or pin a V8 release with published target artifacts so routine test commands do not dead-end.
- Cargo 1.95 on the stable channel exposes `cargo clean gc --help`, but even `cargo clean gc --dry-run` fails because the command is nightly-only. Cleanup diagnostics should check the actual dry-run result (or document a stable fallback) rather than assuming help visibility means GC is usable.
- Repeated invocations of `./scripts/cargo-with-v8.sh test --release ...` rebuilt and relinked the unchanged bettercodex test binary each time, turning a millisecond microbenchmark repetition into roughly 40 seconds per sample. Document using the already-built `target/release/deps/bcodex-*` test executable for repeated measurements, or make the wrapper's generated V8 inputs stable enough for Cargo freshness checks.
- An isolated `cargo run --locked -- --tool-catalogue` fails because `v8 150.4.0` tries to download a nonexistent `librusty_v8_ptrcomp_sandbox_release_x86_64-unknown-linux-gnu.a.gz` (HTTP 404). Document or configure the working V8 archive/source-build path so clean task-owned Cargo targets can reproduce the CLI catalogue.
- Clean Cargo targets try to download rusty_v8 150.4.0 from a release URL that currently returns 404 even though a usable archive is cached at `~/.cache/bettercodex/rusty-v8-150.4.0-<target>/...a.gz`. Document setting `RUSTY_V8_ARCHIVE` to that task-independent source archive when validating with isolated targets.
- A task-owned upstream clone placed in a hidden repository-root directory (`.upstream-codex-ptc`) disappeared during an active source comparison without an explicit cleanup command. Prefer a non-hidden task directory for temporary reference checkouts, or document any workspace cleanup process that removes hidden directories.
