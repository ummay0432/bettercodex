# Papercuts
- `gh` commands in this checkout can infer the read-only `upstream` remote (`openai/codex`) instead of origin, causing misleading 404s for bettercodex workflows. Repository docs or Git config should make `ummay0432/bettercodex` the unambiguous gh default, or examples should consistently pass `-R ummay0432/bettercodex`.
- Cargo 1.95 on the stable channel exposes `cargo clean gc --help`, but even `cargo clean gc --dry-run` fails because the command is nightly-only. Cleanup diagnostics should check the actual dry-run result (or document a stable fallback) rather than assuming help visibility means GC is usable.
- Concurrent sessions can rewrite a task's target files between inspection and compilation without an ownership/change signal, so a diagnostic may compile against a different API than the one just inspected. Surface active file ownership or notify sessions when overlapping files change.
- Searching official OpenAI docs for the exact query “GPT-5.6 Sol prompting guidance” repeatedly returns an enormous, irrelevant changelog/configuration payload and truncates the useful hits. Improve exact-title/model ranking or let callers constrain result fields/output size so the canonical prompting guide is returned compactly.
- The web tool returns HTTP 403 when opening freedesktop.org's canonical systemd man-page URLs, blocking direct authoritative documentation fetches. A documented fallback to systemd's official GitHub man sources, or a fetch user-agent/proxy fix, would avoid repeated dead ends.
