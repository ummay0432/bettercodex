# Papercuts
- `apply_patch` accepted absolute repository paths for earlier patch sections, then unexpectedly removed unrelated documentation in the same tree and failed to find a later absolute path. Use repository-relative paths with `apply_patch`; its interface does not document this constraint.
- Repeated identical `functions.exec` polling cells for a live `write_stdin` session intermittently fail before execution with `SyntaxError: Invalid or unexpected token`; the exec wrapper should make valid retryable polling cells deterministic or expose the offending generated source.
- A plain `git push` reports “Everything up-to-date” on non-main branches because `remote.origin.push` is fixed to `refs/heads/main:refs/heads/main`, even when the current tracked branch is ahead. Document this refspec or use `git push origin HEAD:<branch>` for branch publication.
- While researching GPT-5.6 prompt guidance, `docs/5-5-prompt-guidance.md` looked like stale GPT-5.5 documentation even though its content and the inference guide identify it as GPT-5.6. Rename it to a GPT-5.6-specific filename and update references so agents do not hesitate or open the wrong source.
- Concurrent sessions can move the shared worktree's HEAD between validation and commit; use a dedicated worktree per session or verify and update an explicit branch ref atomically before publishing.
- A multi-file apply_patch reported failure on a later file but silently left earlier file hunks applied, making a failed edit non-atomic. The tool should either roll back prior hunks or explicitly report partial application.
- The JavaScript exec wrapper intermittently returned `SyntaxError: Invalid or unexpected token` for a valid `tools.write_stdin` call; retrying the same call succeeded. Include source location or offending token in exec parse failures so transient harness errors can be distinguished from malformed orchestration code.
- A shared worktree can change between a clean test/Clippy run and `cargo install`, producing failures from another session's transient partial edit. Recheck `git status` and rerun validation against the exact tree immediately before installation.
- An installed interactive TUI smoke launched through `exec_command` with `tty: true` still had no capable `TERM`, so tmux rejected it before startup. Set `TERM=xterm-256color` explicitly for PTY-based bcodex smoke tests, or have the PTY harness provide a suitable default.
