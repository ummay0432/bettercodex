# Papercuts
- The migration probe in docs/install.md treats any binary whose help lists `update` as current, but installed revision e1fa10e4086e still used release-version freshness and refused newer public `main` as a downgrade. Detect revision-aware update behavior explicitly, or direct legacy builds to the canonical installer regardless of the help entry.
- `gh` commands in this checkout can infer the read-only `upstream` remote (`openai/codex`) instead of origin, causing misleading 404s for bettercodex workflows. Repository docs or Git config should make `ummay0432/bettercodex` the unambiguous gh default, or examples should consistently pass `-R ummay0432/bettercodex`.
- GitHub Actions is disabled at the repository level (`GET /repos/ummay0432/bettercodex/actions/permissions` returns `enabled: false`), so newly added active workflows accept no push runs and `gh run list` remains empty. Enable Actions deliberately before relying on native Windows CI.
- A locally installed `x86_64-pc-windows-msvc` Rust target makes Linux cross-checks look available, but `cargo check --target x86_64-pc-windows-msvc` fails deep in native dependencies when `lib.exe` and an MSVC-compatible C toolchain are absent. Document a complete cross-compilation preflight (or state that Windows validation must run on Windows CI) before suggesting this check.
