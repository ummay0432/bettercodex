# Papercuts

- While benchmarking CLI startup, the repository environment had no `/usr/bin/time`, so the usual elapsed-time and peak-RSS command failed. Document an available benchmark command or include a portable helper for startup measurements.
- Using the main worktree's CARGO_TARGET_DIR to validate a detached Git worktree reused a test binary built from the concurrently dirty main checkout, so the supposedly isolated run executed the wrong source. Keep per-worktree Cargo target directories (or document a safe isolation procedure) when validating concurrent work.
- Updating prompts/tool-context.md requires manually reconstructing its byte and tiktoken snapshot because the repository has no documented regeneration command or checked-in helper. Add one command that renders every audited request item and rewrites or verifies the table.
- Validating an isolated BetterCodex worktree with its own Cargo target directory exhausted the filesystem while recompiling the large dependency graph. Document a space-safe isolation workflow or provide a verified way to reuse artifacts without running binaries from the wrong checkout.
- While rerunning a focused Rust test, creation of its temporary rollout failed with ENOSPC because the build/test filesystem was full. Document the repository's safe disk-cleanup targets or add a preflight that identifies removable Cargo and temporary artifacts before validation.
